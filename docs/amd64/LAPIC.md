# LAPIC: Local Advanced Programmable Interrupt Controller

The Local APIC (LAPIC) is the per-processor interrupt controller. Learnix uses its local timer to generate periodic scheduler ticks, and its EOI register to acknowledge interrupts after handling them. The LAPIC timer is calibrated against the HPET because the LAPIC clock rate is not reported directly by this code.

Implementation: [`lapic.c`](../../kernel/arch/amd64/lapic.c) and [`lapic.h`](../../kernel/arch/amd64/lapic.h). The HPET reference is described in [HPET](HPET.md).

## Mapping and enabling the LAPIC

`lapic_init()` reads the physical base from the `IA32_APIC_BASE` MSR (`0x1B`), masking off the low 12 bits that are not part of the page-aligned base (these include APIC control flags). It maps the LAPIC register page at `LAPIC_VIRT_BASE` with write access and caching disabled. LAPIC registers are accessed as volatile 32-bit MMIO values.

The initialization then sets bit 11 in `IA32_APIC_BASE` to enable the APIC. It masks the timer while configuring the controller, writes `0x1FF` to the Spurious Interrupt Vector register (enabling the LAPIC and selecting spurious vector `0xFF`), and configures the timer's divide value to 16.

| Register | Offset | Purpose in Learnix |
|---|---:|---|
| APIC ID | `0x020` | `lapic_get_id()` returns bits 24–31 |
| EOI | `0x0B0` | Acknowledge the current local interrupt |
| Spurious Vector | `0x0F0` | Enable LAPIC; spurious vector `0xFF` |
| Timer LVT | `0x320` | Select timer vector, mode, and mask state |
| Timer Initial Count | `0x380` | Start or reload the timer countdown |
| Timer Current Count | `0x390` | Read the down-counter during calibration |
| Timer Divide Configuration | `0x3E0` | Select the timer's divide-by-16 setting |

The physical base comes from the MSR rather than ACPI. This implementation uses MMIO register access; it does not check for x2APIC mode or provide a legacy-PIC fallback.

## Calibrating the timer

The LAPIC timer counts down, but `lapic_init()` needs an initial count that produces a useful interval. It obtains that count by measuring the LAPIC against the HPET's known clock period:

1. `lapic_ms_to_ticks(10)` converts 10 ms to HPET counter ticks using `FSEC_PER_MS / hpet_get_clk_period()`.
2. It starts the HPET at zero and loads `0xFFFFFFFF` into the LAPIC timer's initial-count register.
3. It polls the HPET until the requested interval has passed, then subtracts the LAPIC current count from `0xFFFFFFFF`. The difference is the number of LAPIC ticks in that interval.
4. `lapic_init()` repeats this measurement `N_CALIBRATION` times (currently five), averages the samples, and divides by ten to get the timer ticks per millisecond.

Averaging reduces measurement noise, particularly in virtual machines. The HPET's period is supplied by the hardware, so this measurement avoids assuming that the LAPIC timer tracks the CPU's changing core frequency. See [HPET: how it calibrates the LAPIC](HPET.md#why-we-need-it) for the reference-counter details.

## Periodic scheduler interrupt

After calibration, `lapic_init()` writes vector `0x20` and periodic mode to the Timer LVT, leaving the timer unmasked. It writes the measured ticks-per-millisecond value to the initial-count register. The timer then raises vector `0x20` periodically; the IDT routes that vector to the timer handler, which calls `sched_tick()` and sends an EOI through `arch_interrupts_eoi()`.

The EOI helper currently ignores its vector argument and writes zero to the LAPIC EOI register. External device interrupts take a separate route through the I/O APIC; the local timer is generated by the LAPIC itself. The distinction and vector registration are covered in [Exceptions and interrupts](exceptions_interrupts.md).

`arch_stage_2()` initializes the HPET first, then the LAPIC, then the I/O APIC. The kernel leaves maskable interrupts disabled through subsystem initialization and enables them in the idle loop, after the timer handler and interrupt routing are ready.
